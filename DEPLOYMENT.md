# Smith's Sales & Services — передача на сервер

В архиве есть исходники сайта, Docker-конфигурация, миграции базы и фотографии автомобилей.
Секреты намеренно не включены.

## Что нужно настроить на сервере

1. Распаковать архив.
2. Создать `backend/.env` на основе `backend/.env.example` и задать надёжные значения:
   - `POSTGRES_PASSWORD`;
   - `POSTGRES_USER` и `POSTGRES_DB` при необходимости;
   - при необходимости задать `BASIN_FORM_ACTION` со ссылкой на собственную форму Smith's Sales & Services в UseBasin. Если оставить поле пустым, заявки сохраняются в базе без пересылки;
   - `BACKEND_CORS_ORIGINS` — фактический домен сайта после его настройки.
3. Перед сборкой фронтенда создать `frontend/.env`:
   ```env
   VITE_API_URL=https://your-domain.example/api
   VITE_META_PIXEL_ID=
   VITE_MAINTENANCE_MODE=false
   ```
   Либо указать отдельный API-домен, если он будет использоваться. В `VITE_META_PIXEL_ID` нужно поставить настоящий ID Meta Pixel; пустое значение отключает пиксель. `VITE_MAINTENANCE_MODE=false` оставляет сайт доступным, а `true` включает технический экран.
4. Настроить Nginx/Apache для выбранного домена: отдавать собранный фронтенд, а `/api` проксировать на backend-порт `8001`.
5. Из папки `backend` запустить:
   ```bash
   docker compose up -d --build
   ```
   Миграции запускаются контейнером API автоматически. На чистой базе будет 16 доступных автомобилей.

## Важно

- `backend/.env` и `frontend/.env` не кладутся в архив: в них находятся серверные адреса и секреты.
- После подключения собственного UseBasin стоит отправить тестовую заявку и убедиться, что она появилась в его панели.
